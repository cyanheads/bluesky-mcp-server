# 0.8.1 — 2026-11-25

## Added

- **`bsky_search_feeds` `actor` mode** lists every feed generator one account created, and feed rows carry `likeCount` in both modes (#70). Pass exactly one of `query` and `actor`. An unknown handle, or one Bluesky rejects as an invalid identifier, fails as `actor_not_found`; an empty first page for a DID is checked with one `app.bsky.actor.getProfile` call bounded to 15 s, which fails a missing account as `actor_not_found` and, if it cannot finish, adds "Bluesky did not confirm that the account exists." to the notice.
- **`bookmarkCount`** on posts from `bsky_get_feed`, `bsky_get_author_feed`, `bsky_get_post_thread`, `bsky_get_post_quotes`, and `bsky_search_posts`, rendered as `N bookmarks` last on the engagement line (#69). Pages cut to the 48,000-byte response budget can hold about one post fewer than before.
- **`totalReturned`** on `bsky_get_list` counts the members, lists, or starter packs on the page, 0 included (#68).

## Changed

- **Handle authorities** in generator-feed, quote, and interaction AT-URIs: a 400 from `com.atproto.identity.resolveHandle` without an XRPC `InvalidRequest` or `HandleNotFound` envelope no longer reads as not found and takes the ordinary error classification (#72).

## Fixed

- **`bsky_get_list` page notices** keep the limit-clamp notice and replace the generic "Raise the cap or narrow with filters." with cursor guidance, even after an empty page; an empty page says whether nothing was found or the previous page was the last (#68).
- **`bsky_get_list` input schema** is a flat object without the root `anyOf`; `invalid_mode` still enforces one mode per call (#71).
- **Handle resolution** goes through one resolver for feeds, quotes, interactions, lists, and starter packs: handles are lowercased, a 400 `InvalidRequest` or `HandleNotFound` maps to the caller's not-found on every path, and a non-DID answer fails as `ServiceUnavailable` (#72).
- **`bsky_get_list` discovery for a DID no account has** fails as `actor_not_found` instead of returning an empty page; the profile check is bounded to 15 s, and one that cannot finish adds "Bluesky did not confirm that the account exists." to the empty page's notice.
- **`bsky_get_list` discovery for an actor Bluesky rejects as an invalid identifier** fails as `actor_not_found` instead of a bare 400 error.
- **A malformed starter-pack record** no longer fails discovery or a direct read: discovery leaves it out and counts it in the notice, and a pack whose backing-list reference is not a list AT-URI returns its metadata with a membership-unavailable notice.
- **An upstream response the server cannot read** fails as `ServiceUnavailable` instead of an invalid-input error.
