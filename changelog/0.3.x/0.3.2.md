# 0.3.2 — 2026-09-20

## Changed

- **`sessionMode: 'stateless'`** is now declared in `createApp()` (mcp-ts-core 0.13.1) instead of relying on the `MCP_SESSION_MODE` deployment default. Unset or empty, the server resolves `stateless` from this declaration; an explicit `MCP_SESSION_MODE` value still overrides it.
- **Out-of-schema tool arguments** are rejected as `InvalidParams` (`-32602`) carrying `structuredContent.error` (mcp-ts-core 0.12.7), with `data.reason: "invalid_arguments"` and a schema-derived recovery hint; a required enum/literal field omitted from input now renders as missing rather than as a wrong choice (0.13.3).
- **Tool error text** in `content[]` now closes with a parenthetical of the terms a caller can branch on — `(reason <reason>)`, adding `· not retryable` when the throw also carries a boolean `data.retryable`; `structuredContent` is unchanged (0.13.5).
- **Tool argument pre-validation**: client-added root keys on a fixed framework ignore list are dropped, a case-folded key spelling matching exactly one declared key is rewritten to it, and a JSON-stringified array is repaired once after a failed parse. An undeclared key is still rejected (0.13.4).
- **Disconnected calls** classify as `RequestCancelled` (`-32011`) and log at `info` instead of surfacing as an internal error (0.12.4), now including a handler unwound after its abort signal fired (0.13.3).
- **Upstream HTTP status mapping**: no status maps to `InternalError` any more — a Bluesky AppView 500 or 501 is `ServiceUnavailable`, a 500 is retried where it previously failed on the first attempt (0.12.4), and a 3xx maps to `InvalidRequest` (0.13.5).
- `/.well-known/mcp.json` publishes the resolved session mode under `_meta` key `io.github.cyanheads.mcp-ts-core/sessionMode` (0.13.2).
- An environment variable set to an empty string or an unsubstituted `${…}` placeholder now reads as unset (0.13.0).
- `SIGTERM`/`SIGINT` end the process explicitly — exit `0` once shutdown settles, `1` if a cleanup step misses the framework's 10-second ceiling (0.13.1).
- Bun engines floor raised to `>=1.4.0` (0.12.9); the skill tree moved from `skills/` to `framework-skills/` so a server shipping a plugin manifest doesn't hand development skills to every installing agent (0.13.0); `.github/workflows/codeql.yml` scaffolded (0.13.3); `audit:fix` corrected to `bun audit fix` (0.13.0).
- `.env.example` and the README env table corrected: `MCP_HTTP_HOST`'s documented default is `127.0.0.1` (0.13.1), and the `MCP_SESSION_MODE` row now states the two-clause resolution rule above in place of the stale "schema default `auto` resolves to stateful" claim.

## Fixed

- `bsky_get_post_thread`'s `post_not_found` error description reads "The AT-URI is well-formed but the post was deleted or never existed", correcting the ungrammatical "is valid format". Clients read this string in the tool's advertised `outputSchema`.
