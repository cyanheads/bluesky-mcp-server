# 0.3.1 — 2026-08-24

## Added

- **Community health files** — `.github/CONTRIBUTING.md` and `.github/CODE_OF_CONDUCT.md`, scaffolded from the mcp-ts-core project template.

## Changed

- **BREAKING: tool inputs are strict.** An argument key a tool's schema doesn't declare is now rejected by name instead of silently dropped, and every advertised `inputSchema` carries `additionalProperties: false`.
- **BREAKING: the advertised `outputSchema` declares the error envelope.** Success fields become optional and `error` is declared, so a client that validates `structuredContent` without checking `isError` no longer rejects error results with `-32602`.
- Every HTTP endpoint now serves protocol revision `2026-07-28` alongside the 2025-era revisions, and the advertised JSON Schema dialect moves from draft-07 to 2020-12.
- `@modelcontextprotocol/sdk` + `@hono/mcp` are replaced by `@modelcontextprotocol/server` + `@modelcontextprotocol/client` under the hood (`@cyanheads/mcp-ts-core` ^0.11.0 → ^0.12.3).
- `bsky_get_post_thread`'s rendered threadgate now names each rule's machine `allow` value beside its plain-language gloss (e.g. "the author's followers (`follower`)") — `content[]` previously gave no way back to the value `structuredContent` carries.
- `.env.example` and the README env var table document `MCP_SESSION_MODE` (`auto`/`stateful`/`stateless`) and `MCP_HTTP_RESUMABILITY`, and recommend `stateless` for this server's HTTP deployment.
- Docker installs omit peer dependencies (`--omit=peer`) to keep the production image lean.
- Project skills re-synced from mcp-ts-core (`api-context`, `api-testing`, `add-tool`, `api-linter`, `api-telemetry`, `api-config`, and others) to document `ctx.requestInput`, strict tool inputs, and the rest of the SDK v2 surface.
