# 0.1.7 — 2026-07-31

## Added

- **`bsky_get_trending`** now returns `actors` on every trend — the five representative accounts the AppView already includes — so "who is talking about this" no longer costs a follow-up `bsky_search_posts` call and an author scan. ([#12](https://github.com/cyanheads/bluesky-mcp-server/issues/12))
- **`src/mcp-server/tools/post-format.ts`** is a new shared markdown renderer (`renderPostLines`, `renderEmbedLines`) used by `bsky_search_posts`, `bsky_get_author_feed`, and `bsky_get_post_thread`. The three formatters had drifted independently — the thread formatter in particular rendered no embeds, CID, author DID, quote count, or indexed timestamp, so a `content[]`-only client saw a materially thinner thread than `structuredContent` carried. ([#10](https://github.com/cyanheads/bluesky-mcp-server/issues/10))
- **`PostView`/`Embed`** gain `replyRootUri` (the AT-URI a reply's conversation started from) and an optional `recordKind` on the `record` embed variant, naming which non-post union member arrived in a quote slot.

## Changed

- **`bsky_get_author_feed`** items that are reposts now carry `repostedBy` (handle, DID, display name) and `repostedAt`, and `author` always names whoever actually wrote the post. The `filter` descriptions no longer claim `posts_no_replies` returns "original posts only" — every filter value includes reposts, since the AppView has no repost filter. ([#9](https://github.com/cyanheads/bluesky-mcp-server/issues/9))
- **`normalizeEmbed`** now dispatches on the exact NSID instead of a substring match, which previously let `app.bsky.embed.recordWithMedia#view` fall into the `record` branch meant for `app.bsky.embed.record#view`.
- **`bluesky-service.ts`**'s outbound `User-Agent` header now reads `config.mcpServerName`/`mcpServerVersion` from the package manifest at runtime instead of a hand-maintained string literal, which had already shipped stale across three prior releases. ([#18](https://github.com/cyanheads/bluesky-mcp-server/issues/18))

## Fixed

- **`app.bsky.embed.recordWithMedia#view`** no longer loses its quoted post or attached media — the quote is unwrapped from `record.record` (one level deeper than a plain `record#view`) and the media is recursed through the same normalizer and nested under `media`. **`app.bsky.embed.gallery#view`** now maps its `items[]` onto the `images` variant, reading the `thumbnail` field gallery uses in place of `images#view`'s `thumb`. ([#7](https://github.com/cyanheads/bluesky-mcp-server/issues/7))
- **A quote that cannot be read or is not a post** — deleted, blocked, detached, or a feed generator/list/starter-pack/labeler in the quote slot — no longer normalizes as an ordinary quote with an empty `cid` and no text. The `record` embed variant carries an optional `recordKind` naming the case, and `format()` states it instead of rendering an empty quote line. ([#15](https://github.com/cyanheads/bluesky-mcp-server/issues/15))
- **`bsky_get_post_thread`'s `format()`** no longer renders every node below the target post twice. `formatThreadNode` already recurses through `node.replies`; the target is now formatted with its own `replies` stripped before the `## This post` section, so `## Replies` no longer re-renders the same subtree. ([#14](https://github.com/cyanheads/bluesky-mcp-server/issues/14))
