# 0.1.6 — 2026-07-31

## Changed

- **`bsky_search_posts`'s `author_handle`, `since`, and `until`** are now `z.union([z.literal(''), <validated-string>])` — an empty string is accepted as "no filter" alongside omitting the field, for form-based clients that send `""` rather than omitting a key.
- **`bsky_search_posts`** no longer advertises a `domain` filter it never implemented — the description and `docs/design.md` both claimed one that didn't exist on the tool.
- **`docs/design.md`** documents the calibration behind the new patterns: an AT-URI authority accepts a handle as well as a DID, and the date filters accept an unpadded month/day in the date-only form but require zero-padding once a time component is present.
- **Test suite**: 96 → 176 tests, covering the new validation boundaries and the `invalid_at_uri`/`post_not_found` split.
- **`scripts/devcheck.ts`** outdated-dependency check no longer fails on peer-dependency rows or on versions held back by `minimumReleaseAge` — it now fails only on packages actually behind within their declared range.
- **`scripts/clean-mcpb.ts` / `scripts/lint-packaging.ts`** strip platform-specific `@duckdb/node-bindings-*` native bindings from `.mcpb` bundles, alongside the existing agent-doc strip.
- **`bunfig.toml`** adds `minimumReleaseAge = 259200` (3-day supply-chain guard on newly published package versions), excluding `@cyanheads/mcp-ts-core` for same-day framework adoption, plus `[install.security] scanner = "@socketsecurity/bun-security-scanner"`.
- **`Dockerfile`** pins the `oven/bun` base image to `1.3.14` (build and production stages), adds BuildKit cache mounts for the Bun install cache, and passes `--ignore-scripts` on the build-stage install.
- **`package.json`** `author` corrected to `Casey Hand <casey@caseyjhand.com>`; `packageManager` bumped to `bun@1.3.14`; `.gitignore`'s `data/` entry root-anchored to `/data/`.
- Added `.gitattributes`, `.github/FUNDING.yml`, `.github/SECURITY.md`; `skills/` and `scripts/` re-synced from the framework template.
- `@cyanheads/mcp-ts-core` `^0.10.9` → `^0.11.0`
- `typescript` `^6.0.3` → `^7.0.2`
- `@biomejs/biome` `2.5.0` → `2.5.5`
- `@types/node` `^26.0.0` → `^26.1.2`
- `tsc-alias` `^1.8.17` → `^1.9.1`
- `vitest` `4.1.9` → `4.1.10`

## Fixed

- **Blank and malformed inputs now fail locally instead of surfacing a generic upstream `Fetch failed ... Status: 400`.** New `src/services/bluesky/at-syntax.ts` holds the AT-identifier, AT-URI, non-blank, and ISO 8601 patterns, applied as Zod `.regex()` validators — and therefore JSON Schema `pattern` constraints — across all seven tool input schemas and the `bsky-profile` resource. `actor`/`query` fields reject blank strings; `bsky_get_post_thread`'s `uri` field requires a full `at://<handle-or-did>/<collection>/<rkey>` shape; `bsky_search_posts`'s `since`/`until` require a valid ISO 8601 date or datetime. ([#4](https://github.com/cyanheads/bluesky-mcp-server/issues/4))
- **`bsky_get_post_thread`** now distinguishes an AppView-rejected AT-URI from a not-found post. The handler's manual `at://` prefix check (which never caught a malformed URI like `at://bad`) is replaced by the new input pattern; a URI that passes the pattern but the AppView still rejects now translates the AppView's own `Invalid at-uri` 400 into the declared `invalid_at_uri` error, kept separate from `post_not_found`. ([#4](https://github.com/cyanheads/bluesky-mcp-server/issues/4))
