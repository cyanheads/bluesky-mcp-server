# 0.2.0 — 2026-07-31

## Added

- **`bsky_get_post_thread`** discloses the author's reply gate via a new optional `threadgate` output field — `uri`, `allow?` (absent means anyone may reply, an empty array means replies are off), and `hiddenReplies` (AT-URIs the author hid). A hidden reply counts toward the reported shortfall only when it is genuinely absent from the returned tree — the AppView still returns some of them. ([#19](https://github.com/cyanheads/bluesky-mcp-server/issues/19))
- **`bsky_get_post_thread`** enrichment gains `totalReturned`, `truncated`, `unreturnedReplies`, and a `notice` summarizing what the response is missing and which part is still reachable by another request. ([#8](https://github.com/cyanheads/bluesky-mcp-server/issues/8))
- Thread nodes now distinguish a blocked post (`blocked: true`, author DID preserved on `post.author.did`) from a deleted one (`notFound: true`); both stubs carry the AT-URI Bluesky reported instead of an empty string. ([#8](https://github.com/cyanheads/bluesky-mcp-server/issues/8))

## Changed

- **BREAKING:** `bsky_get_post_thread`'s `depth` maximum drops from 1000 to 10. Walking 748 live threads at `depth` 1000 (94,366 nodes) found no reply below level 10 regardless of the requested depth — the AppView silently ignores anything past it. `parent_height`'s maximum drops from 1000 to 100, a cost decision rather than an upstream limit: the parent chain is honored level for level, at roughly 1.5 KB per level upstream, and the 99th percentile of 244 sampled chains was 96 posts. A caller passing a larger `depth` or `parent_height` now gets a validation error where it previously got a response. ([#6](https://github.com/cyanheads/bluesky-mcp-server/issues/6))
- Thread nodes report a reply shortfall via `truncated`, `truncationReason` (`"depth"` or `"unavailable"`), and `unreturnedReplies`, replacing the `threadViewPostMore` handling the live AppView never actually returns. `"depth"` means the reply tree ended at that node — fetching its AT-URI as its own thread continues below it. `"unavailable"` means no request closes the gap: Bluesky holds replies back past a per-post limit, and its reply counters keep counting replies that have left the index, and the response has no way to tell the two apart. Read `unreturnedReplies` as an upper bound on what is missing, not a count of readable replies. ([#8](https://github.com/cyanheads/bluesky-mcp-server/issues/8))

## Fixed

- The previous truncation marker — `truncated: true` on a `threadViewPostMore` stub, with guidance to "increase depth" to load the rest — never fired, because the live AppView does not emit that stub. A truncated thread showed no signal at all, and the documented recovery path didn't exist. ([#8](https://github.com/cyanheads/bluesky-mcp-server/issues/8))
