# 0.2.1 — 2026-07-31

## Added

- **`quoteUserText()`** and **`inlineUserText()`** in `post-format.ts` frame Bluesky-authored text as markdown data — blockquote for text that gets its own lines (post bodies, quoted-post bodies, bios, image alt text, link-card titles/descriptions), inline framing (line breaks folded to spaces) for text rendered inside a line the server writes (display names, topic names, moderation labels). ([#5](https://github.com/cyanheads/bluesky-mcp-server/issues/5))
- **`bsky_search_posts`** gains an `upstream_rejected_filter` error contract: when the AppView rejects a search parameter, its own message is surfaced as the error reason and recovery hint instead of a bare `Status: 400`. ([#13](https://github.com/cyanheads/bluesky-mcp-server/issues/13))
- **`BCP47_LANGUAGE_REGEX`**/`BCP47_LANGUAGE_MESSAGE` in `at-syntax.ts` validate the shape of `bsky_search_posts`'s `language` input locally. ([#13](https://github.com/cyanheads/bluesky-mcp-server/issues/13))

## Changed

- **`bsky_get_profile`**, **`bsky_search_actors`**, **`bsky_get_follows`**, **`bsky_get_trending`**, and every post renderer (`bsky_search_posts`, `bsky_get_author_feed`, `bsky_get_post_thread`) now render profile bios, post bodies, quoted-post bodies, image alt text, and link-card titles/descriptions as blockquotes, and fold embedded line breaks to spaces in display names, topic names, and moderation label values. ([#5](https://github.com/cyanheads/bluesky-mcp-server/issues/5))
- **`bsky_search_posts`**'s `hitsTotal` field description and rendered header now state the AppView's 10,000-post cap: a value of exactly 10,000 is a lower bound, not a measured total. ([#11](https://github.com/cyanheads/bluesky-mcp-server/issues/11))
- **`bsky_search_posts`**'s `language` input is validated against BCP-47 shape instead of a bare 10-character length cap; `""` explicitly means no filter. ([#13](https://github.com/cyanheads/bluesky-mcp-server/issues/13))
- Server instructions (`createApp({ instructions })`) document the blockquote/inline framing convention. ([#5](https://github.com/cyanheads/bluesky-mcp-server/issues/5))

## Fixed

- **`bsky_search_posts`**'s truncation enrichment (`truncated`, `shown`, `cap`, `notice`) now actually fires. It was gated behind a branch that only ran when `hitsTotal` was absent, but the AppView returns `hitsTotal` on every response, so the branch was unreachable; it now runs whenever a cursor is returned and either `hitsTotal` is absent or exceeds the returned page. The dead `ctx.enrich.total()` call — writing `totalCount`, a key this tool's enrichment block never declared — is removed. ([#11](https://github.com/cyanheads/bluesky-mcp-server/issues/11))
- **`bsky_search_posts`**'s malformed `language` values (e.g. `"english"`, `"zzzz"`) now fail locally with the expected shape instead of a generic upstream `Status: 400`. ([#13](https://github.com/cyanheads/bluesky-mcp-server/issues/13))

## Security

- Bluesky post bodies, quoted-post bodies, profile bios, image alt text, and link-card titles/descriptions are rendered as markdown blockquotes rather than interpolated directly into `content[]`, so this third-party text can't merge with or read as the server's own markdown structure. This is defense-in-depth framing, not a guarantee against prompt injection. ([#5](https://github.com/cyanheads/bluesky-mcp-server/issues/5))
