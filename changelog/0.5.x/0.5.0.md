# 0.5.0 — 2026-09-25

## Added

- **`bsky_get_post_quotes`** reads the quote posts behind a post's `quoteCount`, newest first, by post AT-URI or bsky.app post URL, without credentials. Each result's embed is cut to the queried post's `uri`/`cid` plus any media the quoting post attached; a missing post or unresolvable handle fails as `post_not_found`. ([#39](https://github.com/cyanheads/bluesky-mcp-server/issues/39))
- **`@handle` and bsky.app URLs as input.** Every `actor` field, `bsky_search_posts` `author_handle`/`mentions`, and `bsky://profile/{actor}` take `@handle` and `https://bsky.app/profile/<actor>`; `bsky_get_post_thread` `uri` takes a bsky.app post URL. A trailing `/`, `?…`, or `#…` is dropped, on `bsky_get_feed` URLs too. ([#38](https://github.com/cyanheads/bluesky-mcp-server/issues/38))
- **`bsky_search_posts` `mentions`, `domain`, and `url`** filters — rich-text mentions of an account, and links (in text or link cards) to a bare hostname, leading `www.` dropped, or to one exact http(s) URL. ([#29](https://github.com/cyanheads/bluesky-mcp-server/issues/29))
- **`bsky_get_author_feed` `posts_with_video`** filter and **`include_pins`**, which puts the profile's pinned post, marked `pinned: true`, first on the first page in addition to `limit`. ([#42](https://github.com/cyanheads/bluesky-mcp-server/issues/42))
- **`bsky_get_follows` `sort`**: `latest` (Bluesky's default) or `top`, Bluesky's own ranking of prominent accounts rather than a follower-count order. ([#43](https://github.com/cyanheads/bluesky-mcp-server/issues/43))

## Changed

- **BREAKING: `bsky_search_posts` `language`** requires a two-letter primary subtag and is sent lowercased. Three-letter codes (`fil`, `eng`), which Bluesky ignored and answered with unfiltered results, are rejected; uppercase (`EN`) now works. ([#28](https://github.com/cyanheads/bluesky-mcp-server/issues/28))
- **BREAKING: `bsky_search_posts` `tag`** rejects a `#`-only or whitespace-only value, which used to turn the filter off silently. The tag is sent without its `#`, so `#ai` and `ai` match the same posts. ([#29](https://github.com/cyanheads/bluesky-mcp-server/issues/29))
- **BREAKING: a malformed `cursor` fails as `invalid_cursor`** after one request on `bsky_get_author_feed`, `bsky_get_post_quotes`, `bsky_search_actors`, and `bsky_search_posts`, where it used to be a retried 500 or a bare fetch failure. ([#41](https://github.com/cyanheads/bluesky-mcp-server/issues/41), [#44](https://github.com/cyanheads/bluesky-mcp-server/issues/44))
- **`quoteCount`** descriptions point to `bsky_get_post_quotes` and call the count an upper bound; `bsky_get_post_thread` states it returns replies only.

## Fixed

- **`bsky_search_posts` `hitsTotal`** is described and rendered as Bluesky's estimate: below 10,000 an upper bound on what paging returns (`Up to N matching posts`), at 10,000 a floor. `truncated` keys on the returned cursor alone, which Bluesky omits once results are exhausted. ([#27](https://github.com/cyanheads/bluesky-mcp-server/issues/27))
- **`bsky_search_posts` `since`/`until`** descriptions say both bounds compare against the earlier of `createdAt` and `indexedAt`, and that a date alone means 00:00:00 UTC. ([#27](https://github.com/cyanheads/bluesky-mcp-server/issues/27))
- **An empty page that carries a cursor** keeps the cursor footer in `content[]` on `bsky_get_follows`, `bsky_get_feed`, `bsky_get_author_feed`, `bsky_search_actors`, and `bsky_search_posts`; the no-results notice appears only when no cursor came back. ([#45](https://github.com/cyanheads/bluesky-mcp-server/issues/45))
- **`bsky_get_author_feed` `filter`** descriptions: the two media filters return no reposts, and `posts_with_media` excludes link cards. ([#42](https://github.com/cyanheads/bluesky-mcp-server/issues/42))
