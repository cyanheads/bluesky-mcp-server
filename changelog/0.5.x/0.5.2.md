# 0.5.2 — 2026-10-08

Tool input and output schemas are unchanged.

## Changed

- **`@cyanheads/mcp-ts-core` `^0.13.6` → `^0.13.14`**: tool error results carry `data.requestId` and their text closes with `request <id>` (0.13.10).
- **Input repair before validation**: a numeric or boolean string sent for a number or boolean input, and `null` sent for an optional input, are repaired (0.13.14), as is an integer sent for a string input (0.13.9).
- **Error data is leaner**: it no longer carries stack traces (0.13.7), request context ([cyanheads/mcp-ts-core#548](https://github.com/cyanheads/mcp-ts-core/issues/548), 0.13.8), or `rootCause` (0.13.13). A result that breaks a tool's output schema fails as `-32603` ([cyanheads/mcp-ts-core#480](https://github.com/cyanheads/mcp-ts-core/issues/480), 0.13.8).
- **Errors**: service and tool errors no longer forward their own recovery hint (`ctx.recoveryFor` calls removed); the framework fills the hint declared on each tool's error contract (0.13.10), so the hints callers see are unchanged.
- **Dockerfile** installs production dependencies in a `deps` stage pinned to the build platform, so multi-arch builds no longer run Bun under emulation (0.13.10), and prunes musl-only native packages (0.13.11). New scripts `scripts/install-otel.ts` and `scripts/prune-musl-packages.ts`; `oven/bun` `1.4.0` → `1.4.2`; `MCP_FORCE_CONSOLE_LOGGING` is no longer set in the image.
- **MCP Registry entry** (`server.json`): the npm package runs through `npx` with no `run` / `start:stdio` arguments, and the Streamable HTTP entry sets `MCP_TRANSPORT_TYPE=http` ([cyanheads/mcp-ts-core#622](https://github.com/cyanheads/mcp-ts-core/issues/622), 0.13.11).
- **Template sync**: framework skills, devcheck and lint scripts, the CodeQL workflow (one job per language), `.gitignore` / `.dockerignore` `.env*` patterns, `.mcpbignore`, `.env.example` (opt-in `LOG_TOOL_FAILURE_PAYLOADS` and OTLP endpoint variables), and `AGENTS.md` / `CLAUDE.md` brought to 0.13.14.
