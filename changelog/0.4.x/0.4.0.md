# 0.4.0 — 2026-09-25

## Added

- **`bsky_get_feed`** reads a feed generator's posts by AT-URI or `https://bsky.app/profile/<actor>/feed/<rkey>` URL, always unauthenticated. A handle owner is resolved to its DID first, pinned items carry `pinned: true`, and failures map to `feed_not_found`, `feed_unavailable` (not retried), or `feed_requires_login`. ([#35](https://github.com/cyanheads/bluesky-mcp-server/issues/35))
- **`BLUESKY_IDENTIFIER` / `BLUESKY_APP_PASSWORD`** (optional, set both or neither — one alone fails startup) enable `bsky_search_posts`, which then runs as that account through its PDS: login on the first search, never at startup, then session reuse and refresh. Failures surface as `search_auth_failed`, `search_login_limited`, or `search_refused`. Declared in `server.json`, `manifest.json`, and both plugin manifests. ([#32](https://github.com/cyanheads/bluesky-mcp-server/issues/32))
- **`bsky_get_trending`** trends carry `feedUri` (the trend feed's AT-URI, parsed from `link`, for `bsky_get_feed`) and `description` (Bluesky's one-sentence story summary, rendered quoted). `topic` is now documented as the feed's record key, not a search term. ([#34](https://github.com/cyanheads/bluesky-mcp-server/issues/34))
- **`bsky_get_post_thread`** rejects a feed generator AT-URI before any request as `uri_is_feed`, pointing to `bsky_get_feed`.

## Changed

- **BREAKING: `bsky_search_posts` is absent from `tools/list` without `BLUESKY_IDENTIFIER` and `BLUESKY_APP_PASSWORD`.** It was listed before and failed on every call, since Bluesky now refuses unauthenticated search. The server instructions follow the same switch, and no other tool's text names search as a source. ([#32](https://github.com/cyanheads/bluesky-mcp-server/issues/32))
- **BREAKING: `followersCount` / `followsCount` removed** from `bsky_search_actors` `actors[]` and `bsky_get_follows` `actors[]` and `subject`. Bluesky's `profileView` never carries them, so they were never populated; `bsky_get_profile` has the counts. ([#36](https://github.com/cyanheads/bluesky-mcp-server/issues/36))

## Fixed

- **`bsky_get_trending` `truncated`** is set only when more topics are trending than `limit` (the handler requests one past it), so never at `limit: 25`, Bluesky's maximum. ([#25](https://github.com/cyanheads/bluesky-mcp-server/issues/25))
- **`bsky_get_follows` / `bsky_search_actors` `truncated`** keys on a returned cursor whatever the page size; an empty continuation page reports that the previous page was the last instead of the no-match notice. ([#25](https://github.com/cyanheads/bluesky-mcp-server/issues/25))
- **`bsky_search_actors` cursor** is described as working pagination rather than 403-prone, and the truncation notice reads `Pass the returned cursor to fetch the next page of actors.` ([#37](https://github.com/cyanheads/bluesky-mcp-server/issues/37))
- **Upstream error data** no longer carries the HTML block page Bluesky's edge answers some requests with; the status remains.
